# ADR-029 — ISO 22400 KPIs Worker (Endpoint + Dashboard Operacional)

**Código:** CSN-L3-PER-ADR-029-2026  
**Data:** 31/03/2026  
**Estado:** ✅ Aceite  
**Sessão:** 33–34  
**Nível ISA-95:** L3-PER (Personnel Operations / Performance)

---

## Contexto

O sistema já registava execução (fases, timetracking), mas faltava um mecanismo padronizado para análise de performance individual alinhado com **ISO 22400** no contexto de MOM/MES.

Era necessário:

- disponibilizar KPIs de trabalhador em endpoint próprio;
- apresentar os KPIs numa vista operacional simples para o próprio operador;
- manter coerência de contrato entre backend e frontend (payload estável).

---

## Decisão

Definir o bloco **KPIs Worker ISO 22400** com:

1. **Endpoint dedicado** `/api/kpis/worker?colaborador_id=X`  
   Retorna período, KPIs e obra atual em curso.

2. **KPIs base implementados**
   - Worker Efficiency Ratio
   - Actual Production Time (semana)
   - Actual Production Time (mês)
   - Throughput Rate (semana)
   - Throughput Rate (mês)
   - Allocation Efficiency

3. **Dashboard Worker no modo produção**
   - Gauges de eficiência
   - Barras de throughput
   - Progresso da obra atual

4. **Contrato de dados explícito**
   - `obra_actual` com `obra_id`, `descricao`, `chassis`, `total_fases`, `fases_concluidas`, `fase_actual`, `percentagem`, `inicio_timer`
   - Sem campos ambíguos/duplicados no payload.

---

## Declaração Camada 2 vs Camada 3

| Componente | Camada | Papel |
|-----------|--------|-------|
| `WorkerDashboard.tsx` (visualização, gauges, barras, layout) | **Camada 2** | Apresenta informação ao trabalhador; não calcula regras de negócio |
| `/api/kpis/worker` + queries Supabase + fórmulas KPI | **Camada 3** | Calcula indicadores, consolida dados e publica contrato canónico |

**Regra:** KPI é calculado no núcleo (Camada 3); a interface (Camada 2) apenas consome e apresenta.

---

## Consequências

**Positivas**

- Introduz medição operacional padronizada por trabalhador (ISO 22400).
- Melhora feedback imediato ao operador no Modo Produção.
- Cria base para evolução de KPIs adicionais (Setup Ratio, OEE, FPY, energia).
- Aumenta maturidade MESA-11 em Performance Analysis.

**Trade-offs**

- Requer qualidade de dados de origem (fases/timers corretos).
- Mudanças no payload do endpoint exigem versionamento disciplinado no frontend.

---

## Notas de Implementação

- Endpoint deve tolerar ausência de timer ativo (`maybeSingle`) e retornar `obra_actual: null` quando aplicável.
- O dashboard deve evitar inferências locais de campos não canónicos.
- Extensões futuras de KPI mantêm retrocompatibilidade do contrato sempre que possível.
